# Аудит изменений после v1.0.76

Дата аудита: 2026-07-21.

База: `v1.0.76` (`c1bcf86`). Проверенный диапазон: 13 коммитов до
`a7e3f75`. Итоговое дерево новой ветки меняло 59 файлов: 7789 добавлений и
2447 удалений. Первый hardening-коммит сам по себе менял 61 файл (7711/2563),
поэтому его нельзя считать одним изолированным исправлением.

## Критические выводы

1. Первоначальный hardening поменял polkit с `allow_active=yes` на
   `auth_admin_keep` и одновременно убрал рабочий self-heal. Для существующей
   установки это превращало расхождение helper-файлов в жёсткий отказ
   подключения.
2. Новый Linux helper принимает только публичные IPv4 endpoint-адреса. Это
   меняет поддерживаемую конфигурацию и ломает private/self-hosted VPN без
   отдельного продуктового решения и тестов.
3. В новом Linux `stop` routing cleanup не выполняется, если сначала не удалось
   восстановить DNS. Это fail-closed, но оставляет процессы/маршруты активными и
   требует отдельного recovery UX; переносить такой контракт скрытно нельзя.
4. Новый Windows DNS guard сделал DNS reset частью критического cleanup. Ошибка
   позднего reset уже приводила к ложному `Error`, недоступным ping и зависшему
   состоянию кнопки; это подтверждают коммиты `34e5901` и `a7e3f75`.
5. Linux watchdog в новой реализации пытался читать `/proc/<pid>/exe` root-
   процесса из desktop-процесса и принимал `EACCES` за смерть tun2socks. База
   `v1.0.76` уже корректно считает процесс живым при недоступном `/proc`.
6. Успешная CI-сборка `v1.0.80` доказала только компиляцию и unit-тесты, но не
   корректность реальных Windows/Linux routes, DNS, polkit и process lifecycle.

## Перенесённые изменения

- `readSubscriptionUrl()` больше не блокирует загрузку серверов/подключение на
  bot API при пустом кеше. Прямой subscription URL строится из `shortUuid`, а
  bot URL обновляется в фоне. In-flight запросы разделены по аккаунтам, и
  результат старого аккаунта не может записаться в текущую сессию.
- Xray traffic counter парсится как `u64`: полный диапазон не теряется, а
  отрицательное/повреждённое значение больше не превращается в положительное
  через `unsigned_abs()`.
- CI проверяет совпадение версий package/Tauri/Cargo, TypeScript, Rust format,
  Linux Clippy и Rust tests на Linux/Windows.

## Дополнительный безопасный перенос

Из большого hardening-набора отдельно перенесены только изменения, не
затрагивающие маршруты, DNS и жизненный цикл VPN-процессов:

- `ServerConfig` получает структурную проверку до первого изменения нативного
  сетевого состояния: отсекаются нулевой порт, некорректный VLESS user ID,
  неизвестный routing mode, управляющие символы и чрезмерные списки/строки.
  В отличие от поздней реализации, сохранены официально поддерживаемые custom
  VLESS ID короче 30 байт, приватные IPv4, loopback и IPv6; они покрыты тестом.
- Root-updater принимает пакет только из ожидаемого HTTPS release-path
  `Shoolife/ToBeVPN-Desktop` и только для запрошенной версии. Manifest ограничен
  256 KiB, пакет — 256 MiB; это закрывает произвольный URL и безлимитное чтение
  в память. Вызовы `dpkg`/`dpkg-deb` используют абсолютные системные пути.
  Polkit entrypoint запускает только root-owned, не writable установленный
  бинарник из фиксированного `/usr/bin`, с очищенным окружением; поиск через
  унаследованный `PATH` удалён.
- GitHub Actions закреплены по полным commit SHA. Rust закреплён на `1.94.1`,
  `cargo-audit` — на `0.22.1`. Xray закреплён на уже используемой стабильной
  версии `v26.3.27`, а Linux/Windows архивы и Wintun проверяются по SHA-256.
- Генерация `latest.json` требует ровно один installer и соответствующую ему
  непустую `.sig`, ограничивает размер подписи и формирует JSON через `jq`, а
  не строковую подстановку в heredoc.
- WebView оставлены только фактически используемые Tauri permissions: listen/
  unlisten событий, resize/drag/minimize/close окна, updater, exit/restart,
  scoped HTTP и открытие Telegram/legal URL. Убраны frontend event emit,
  произвольное открытие URL/файлов и неиспользуемый `wasm-unsafe-eval`; при
  этом сохранены drag и fallback-close, ошибочно потерянные в позднем варианте.

## Второй проход по независимым исправлениям

После первичного отката повторно проверены не только границы коммитов, но и
отдельные изменения внутри больших squash-коммитов. Дополнительно перенесены:

- API больше не повторяет `POST`/другой изменяющий состояние запрос после
  потери ответа или `401`: это исключает двойную покупку, регистрацию или
  unlink. Повтор через резервный endpoint и replay после refresh разрешены
  только для `GET`/`HEAD`. Ошибки очищаются от токенов и URL с credentials.
- Все долгие account-запросы привязаны к поколению сессии и device/account ID.
  Ответ старого аккаунта не может восстановить его токены, серверы, аватар,
  профиль или purchase polling после logout/повторной привязки. Pending purchase
  хранится отдельно для аккаунта, имеет TTL и не переносит платёжные URL между
  запусками.
- Сохранён совместимый plaintext fallback для Linux без Secret Service, но
  операции keyring упорядочены, logout сначала ставит durable tombstone, а
  нативная запись ограничена 64 KiB. Это закрывает позднее «воскрешение» токена,
  не включая новый режим, который мог бы постоянно выбрасывать пользователя
  из аккаунта на системах без keyring.
- Успешный пустой subscription response теперь считается авторитетным:
  отозванный/удалённый сервер не возвращается из старого выбора. При сетевой
  ошибке офлайн-fallback остаётся. Метаданные узлов сопоставляются по
  `address:port`, UTF-8 имена из base64 подписки декодируются корректно, а
  размеры списков, ссылок, доменов и числовых полей ограничены.
- Закрыты UI-race: параллельные QR/pairing poll, повторное открытие Telegram,
  двойной unlink/покупка, старый ping/load списка серверов, смена аккаунта в
  Settings и старый speed-test больше не перезаписывают актуальное состояние.
  Speed-test получил timeout для зависшего body-read и backoff вместо hot loop.
- Stats JSON проверяется, читается только из regular file, восстанавливается из
  backup и записывается атомарно с `fsync`. Бакеты ограничены и проверены,
  миграция не теряет runtime delta, а границы дня/недели/месяца учитывают DST и
  неполную пятую неделю.
- Конфигурационные URL валидируются как HTTPS без credentials; updater не
  принимает подменённую версию между показом и установкой. CI отклоняет пустые
  production hosts, но PR-сборки используют `example.invalid`. Исправлен
  воспроизведённый случай, когда restore-скрипт путал BOT/PANEL placeholders при
  одном общем домене.
- Windows hardware model запрашивается через абсолютный системный PowerShell с
  очищенным окружением; fingerprint ограничен по времени/размеру. Linux
  `install-polkit.sh` корректно находит свои файлы при запуске из любой папки,
  desktop entry нормализует URL placeholder.

Polkit policy и сетевой helper при этом не менялись. Для активной локальной
сессии стабильная policy по-прежнему содержит `<allow_active>yes</allow_active>`:
после одноразовой установки helper это изменение не добавляет запрос пароля на
каждое подключение. Пароль возможен при самой первой установке/восстановлении
отсутствующего helper либо при запуске вне активной desktop-сессии.

Сознательно не перенесены новый network-helper/DNS/routes state machine,
update-lock, сериализация VPN polling/disconnect, Windows elevated-autostart
rewrite, новый контракт применения routing settings и pin более новых routing-
датасетов. Не удалён совместимый keyring fallback. Эти изменения затрагивают
привилегированный жизненный цикл туннеля или миграцию логина и должны идти
отдельными OS-tested PR; именно этот слой уже создавал Windows/Linux регрессии.

## Сверка с Android v1.0.53

Android-коммит `d0fa0db` проверен пофайлово, а не перенесён целиком. В desktop
добавлены только совпадающие по причине дефекты:

- VLESS query больше не применяет form-семантику к литеральному `+`, поэтому
  WebSocket/XHTTP paths и Reality-параметры не превращаются в строки с
  пробелами. Некорректно экранированный fragment больше не выбрасывает весь
  сервер; bracketed IPv6 literal нормализуется перед передачей нативному слою.
- Nullable `status`, `traffic_limit_strategy`, `traffic_limit_bytes` и
  `active_internal_squads` из panel API не роняют синхронизацию. Отсутствующий
  список устройств трактуется как пустой, но значение неверного типа всё ещё
  отклоняется.
- ISO timestamp с явным offset сохраняет его, а timestamp без offset трактуется
  как UTC, как на panel. Это исключает сдвиг срока подписки часовым поясом ПК.
- Прогресс updater использует локализованные `МБ`/`MB` и в обычном баннере, и
  в обязательном update-dialog.

Уже присутствовали независимо: whole-word определение страны (`Ukraine` и
`Baku` не становятся `UK`), локальные границы понедельник-воскресенье и
DST-safe диапазоны статистики, локальные подписи часов, а также единая тема для
splash/updater/dialog. React-экраны не держат Android-подобный пятисекундный
server-ping loop после размонтирования. Purchase plans уже проходят строгую
runtime-санитизацию с безопасными пустыми массивами; GitHub asset/Gson и
OkHttp `errorBody` не имеют прямого аналога в Tauri updater/fetch.

Не переносились Android `ForegroundService`, ограничения фонового запуска
service, `onDestroy` generation, `Runtime.exit`, Compose `Color.toArgb()` и
debounce фильтра приложений: у desktop другие Tauri/Rust lifecycle, CSS chart и
явная кнопка применения routing. Исправление self-cancel email prompt также не
переносилось: desktop не показывает такой prompt после pairing, email остаётся
явной настройкой аккаунта. Нативные Windows/Linux VPN managers в этой сверке не
менялись. Полная поддержка VPN endpoint по IPv6 также не заявлена: текущий
routing-контракт desktop по-прежнему требует физический IPv4 endpoint.

## Дозакрытие Android v1.0.54

Первичный перенос `8c5d969` убрал bot lookup из `readSubscriptionUrl()`, но
несколько вызывающих сценариев всё ещё сами ставили `syncSubscription()` перед
прямым запросом. Они исправлены отдельно:

- при холодном старте bot sync и `fetchVpnServers()` запускаются одновременно
  и ограничены тем же startup timeout;
- Home запускает прямое обновление серверов независимо от фонового plan sync;
- подготовка подключения и ручной Refresh больше не ставят bot API перед
  subscription endpoint.

Bot sync сохранён для plan metadata, смены subscription URL и данных аккаунта,
но выполняется в фоне там, где доступ уже можно авторитетно проверить прямым
subscription response. Проверки HWID/block state, поколение сессии и защита от
ответов старого аккаунта не ослаблены.

  GitHub API; SHA-256 Wintun проверен по официальному архиву
- `git diff --check`

Попытка локального `cargo check --target x86_64-pc-windows-msvc` на Linux
остановилась на отсутствии MSVC `lib.exe` и Windows sidecar, а не на ошибке
исходников. Поэтому Windows-компиляция должна быть подтверждена штатным CI; она
не заменяет реальный smoke-test.

Перед следующим релизом обязательны ручные smoke-тесты на реальных ОС:

- Windows: clean install/upgrade, connect, live switch, disconnect, reconnect,
  crash recovery, sleep/resume и запуск без оставшегося Wintun adapter;
- Linux: upgrade существующего `.deb`, отсутствие повторного polkit prompt,
  connect дольше watchdog interval, live switch, disconnect, DNS restore,
  sleep/resume и запуск после принудительного завершения процесса.

Новые killswitch/DNS/helper/state-machine изменения можно возвращать только
маленькими независимыми PR с такими integration-тестами, а не общим squash.
