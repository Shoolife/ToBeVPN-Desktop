# Аудит изменений после v1.0.76

Дата аудита: 2026-07-21.

База: `v1.0.76` (`c1bcf86`). Проверенный диапазон: 13 коммитов до
`a7e3f75`. Итоговое дерево новой ветки меняло 59 файлов: 7789 добавлений и
2447 удалений. Первый hardening-коммит сам по себе менял 61 файл (7711/2563),
поэтому его нельзя считать одним изолированным исправлением.

## Критические выводы

1. Первоначальный hardening поменял polkit с `allow_active=yes` на
   `auth_admin_keep` и одновременно убрал рабочий self-heal. Для существующей
   установки это превращало расхождение helper-файлов в жёсткий отказ
   подключения.
2. Новый Linux helper принимает только публичные IPv4 endpoint-адреса. Это
   меняет поддерживаемую конфигурацию и ломает private/self-hosted VPN без
   отдельного продуктового решения и тестов.
3. В новом Linux `stop` routing cleanup не выполняется, если сначала не удалось
   восстановить DNS. Это fail-closed, но оставляет процессы/маршруты активными и
   требует отдельного recovery UX; переносить такой контракт скрытно нельзя.
4. Новый Windows DNS guard сделал DNS reset частью критического cleanup. Ошибка
   позднего reset уже приводила к ложному `Error`, недоступным ping и зависшему
   состоянию кнопки; это подтверждают коммиты `34e5901` и `a7e3f75`.
5. Linux watchdog в новой реализации пытался читать `/proc/<pid>/exe` root-
   процесса из desktop-процесса и принимал `EACCES` за смерть tun2socks. База
   `v1.0.76` уже корректно считает процесс живым при недоступном `/proc`.
6. Успешная CI-сборка `v1.0.80` доказала только компиляцию и unit-тесты, но не
   корректность реальных Windows/Linux routes, DNS, polkit и process lifecycle.

## Перенесённые изменения

- `readSubscriptionUrl()` больше не блокирует загрузку серверов/подключение на
  bot API при пустом кеше. Прямой subscription URL строится из `shortUuid`, а
  bot URL обновляется в фоне. In-flight запросы разделены по аккаунтам, и
  результат старого аккаунта не может записаться в текущую сессию.
- Xray traffic counter парсится как `u64`: полный диапазон не теряется, а
  отрицательное/повреждённое значение больше не превращается в положительное
  через `unsigned_abs()`.
- CI проверяет совпадение версий package/Tauri/Cargo, TypeScript, Rust format,
  Linux Clippy и Rust tests на Linux/Windows.

- `cargo clippy --locked --all-targets -- -D warnings`
- `cargo test --locked --all-targets` — 7/7 Linux tests

- `npm run build` с безопасными placeholder endpoint-ами
- `git diff --check`

Перед следующим релизом обязательны ручные smoke-тесты на реальных ОС:

- Windows: clean install/upgrade, connect, live switch, disconnect, reconnect,
  crash recovery, sleep/resume и запуск без оставшегося Wintun adapter;
- Linux: upgrade существующего `.deb`, отсутствие повторного polkit prompt,
  connect дольше watchdog interval, live switch, disconnect, DNS restore,
  sleep/resume и запуск после принудительного завершения процесса.

Новые killswitch/DNS/helper/state-machine изменения можно возвращать только
маленькими независимыми PR с такими integration-тестами, а не общим squash.
